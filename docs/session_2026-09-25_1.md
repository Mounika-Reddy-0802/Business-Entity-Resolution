# Session 2026-09-25 #1 (unattended, from 00:52 IST)

## Read this first

The organiser dataset and `utils/validate_submission.py` were **not on this machine**
(docs/problems.md). Everything was built and measured on a synthetic stand-in with the exact
schema. The pipeline is complete and validated end to end, but **`output/matching_results.tsv`
currently holds predictions for the synthetic test set and must not be uploaded.**

To produce the real submission:

1. `rm -rf data/` (removes the synthetic data and every cache).
2. Put the organiser files in `data/raw/dataset/train/`, `data/raw/dataset/test/` and
   `utils/validate_submission.py`.
3. `bash scripts/run_pipeline.sh` — split, blocking, features, two-stage LightGBM, decision sweep,
   retrain on full train, test outputs, organiser validator, local checks and sanity report.
4. Check the sweep's printed validation F0.5 and the sanity report, run
   `python -m src.common.eda` and `python -m src.matching.cross_country --log`, log rows, commit.
5. The file to upload is `output/matching_results.tsv` after the organiser validator prints PASS.

## Numbers (synthetic v2; benchmarks/experiments.md)

- Blocking recall 0.997 at 40 candidates per S1 entity.
- Val F0.5: 0.9791 (LightGBM, t=0.5) → 0.9799 (threshold, one-to-one) → 0.9809 (drop is_s3)
  → 0.9838 (stage-2 context model) → **0.9842** (learning rate 0.02; best of 14 one-change
  LightGBM variants via `python -m src.matching.tune`, all other variants lower).
- Seed noise (`python -m src.matching.stability`): 5-seed mean 0.9831, std 0.0012; seed 42 is
  the best seed, so 0.9842 is optimistic. Only stage 2 (+0.0029) clearly exceeds the noise.
- Cross-country: India→US 0.9735, US→India 0.9663.
- Embeddings (MiniLM, Apache-2.0) did not help on synthetic data (0.9811 / 0.9813) and are off.
- Full pipeline: 201 s at 10k training S1 entities; 605 s at 4x.
